# Архитектура Gifty AI

## Границы приложения

`frontend/` — Next.js App Router, React, TypeScript, Tailwind CSS 4, shadcn/ui-подход с локальными Radix-компонентами, Lucide, Framer Motion. Русский интерфейс, локальные шрифты и оригинальные SVG-иллюстрации. Состояние интерфейса не заменяет базу: после перезагрузки данные запрашиваются у API.

`backend/` — FastAPI, Pydantic, SQLAlchemy 2 и Alembic. Основная база — PostgreSQL 17; SQLite предназначена для локальной разработки без Docker. Время сессий и записей хранится в UTC, события рассчитываются для Москвы.

Браузер обращается к `/api/*` на том же origin. Next.js Route Handler проксирует только в фиксированный `API_ORIGIN`, передаёт session-cookie и Origin, ограничивает размер запроса, не отдаёт ключи интеграций. FastAPI дополнительно проверяет Origin, размер, сессию, владение каждым объектом и лимит запросов. При недоступном backend интерфейс показывает ошибку с возможностью повторить запрос.

## Сущности и жизненный цикл

| Сущность | Связи и назначение |
| --- | --- |
| User | Аккаунт, настройки, разрешения и веса критериев |
| AuthSession | Хеш случайного токена, пользователь, срок действия |
| Recipient | Принадлежит User; имя, интересы, ограничения, основание обработки |
| RecipientInterest | Принадлежит Recipient; вес, источник, происхождение, подтверждение |
| SocialImport | Исходный текст, метка и ссылка источника, идентификаторы полученных интересов |
| GiftOccasion | Принадлежит User; необязательная связь с Recipient; повторение и срок напоминания |
| Product | Общий нормализованный каталог; происхождение и дата обновления |
| GiftRequest | Принадлежит User; снимок получателя, бюджет, запрос, переписка и анализ |
| Recommendation | Принадлежит GiftRequest; товар, позиция, объяснение и составляющие оценки |
| Favorite | Уникальная пара User / Product |
| GiftCollection / CollectionItem | Пользовательский набор, бюджет, сохранение, ссылки на товары |
| GiftHistory | Принадлежит User и Recipient; уже подаренные товары или названия |

Владение проверяется по `object.id AND object.user_id == current_user.id`, в том числе для наборов, событий и импортов. Чужие объекты возвращают 404. Идентификаторы дочерних элементов дополнительно проверяются внутри принадлежащего пользователю объекта.

Удаление импорта удаляет исходный текст и все созданные им интересы, включая впоследствии подтверждённые. Источник интереса нельзя подменить при редактировании. Удаление получателя удаляет интересы, импорты, события, историю подарков и его подборки с копиями имени и переписки. Сохранённый набор после удаления получателя остаётся без связи с ним. Удаление аккаунта каскадно удаляет все его записи; общий публичный каталог сохраняется.

## Подбор

1. API проверяет владение профилем и входные данные. Умный режим возвращает три уточняющих вопроса и начинает подбор после ответов.
2. AI Provider извлекает интересы, исключения, предпочтение оригинальности/практичности и бюджет. Результат проходит строгую Pydantic-валидацию. Ответ провайдера не содержит товаров.
3. Из текста дополнительно извлекаются явные запреты локальным анализатором. Бюджет из текста может только уменьшить бюджет формы.
4. `GiftRecommendationEngine` собирает подтверждённые интересы профиля, ограничения и историю подарков. Неподтверждённые выводы импорта не участвуют в ранжировании.
5. Из нормализованного каталога исключаются дорогие, недоступные, запрещённые, повторные товары и дубликаты названий.
6. Рассчитываются шесть критериев: интересы, бюджет, повод, оригинальность, практичность и новизна. Веса пользователя нормируются. Стилевые пожелания могут усилить оригинальность и практичность. При отсутствии специальных правил оценка повода нейтральна и не заявляет экспертное понимание уместности.
7. До восьми результатов сохраняются с объяснениями, порядком и составляющими оценки. При недостатке подходящих товаров возвращается меньше идей либо честный пустой список.

Демоанализ использует фиксированный словарь русских основ и простые правила отрицаний и бюджета. Он детерминирован, но не является полноценной языковой моделью: сложные формулировки могут потребовать уточнения. Свободный текст не превращается в подтверждённые факты профиля.

## Каталоги

`CatalogProvider` → `MockCatalogProvider`, `OzonProvider`, `WildberriesProvider`, `YandexMarketProvider`.

Три внешних адаптера читают **разрешённый оператором JSON-экспорт** партнёрского каталога. Они не вызывают Seller API для поиска по всему потребительскому рынку и не сканируют сайты. Для прямых карточек проверяются HTTPS и домен соответствующего магазина. Пустой путь экспорта означает отсутствие подключения.

`MockCatalogProvider` содержит 38 условных идей с оригинальными иллюстрациями. Их `source=mock`, `availability=demo`, `product_url=null`. Поисковые URL строятся из названия с кодированием запроса. Наличие, доставка, рейтинги и реальная цена не выдумываются. Демотовары сохраняются рядом с разрешёнными экспортами и всегда помечены в интерфейсе.

## Внешний ИИ и голос

`AIProvider` имеет реализации Demo, OpenAI-compatible, YandexGPT и GigaChat. HTTP-клиенты проверяют TLS, имеют таймауты и валидируют JSON. Авторизация GigaChat использует предоставленный оператором актуальный access token; автоматический OAuth-refresh в MVP не реализован.

Вызов внешнего ИИ требует одновременно настройки провайдера, `EXTERNAL_PROCESSING_ENABLED=true`, разрешения пользователя в настройках и выбора внешнего анализа в текущем запросе. Контекст автоматически включает только подтверждённые интересы, бюджет и повод; текст запроса передаётся как введён, поэтому интерфейс запрещает добавлять в него чувствительные сведения. Имена, дни рождения, заметки и исходные импорты автоматически не передаются. Проверку применимых правовых оснований и условий провайдера выполняет оператор до включения интеграции.

SpeechKit вызывается только сервером после отдельного разрешения пользователя. Доступ к микрофону запрашивается при нажатии записи. Запись ограничена 25 секундами; сервер принимает до 1 МБ. OggOpus передаётся в SpeechKit v1 напрямую; WebM/Opus преобразуется FFmpeg в памяти, без shell и файлов. Полученный текст открывается в редактируемом диалоге и не отправляется автоматически.

## Ограничения MVP перед публичным запуском

Это локальное работающее MVP, а не утверждение о юридической готовности сервиса. В частности:

- Разместить основную базу и необходимые сервисы с учётом требований оператора к локализации; отдельно проверить условия внешней обработки и возможной трансграничной передачи.
- Утвердить политику с реквизитами оператора, каналом обращений, основаниями, сроками хранения и порядком удаления резервных копий. Встроенная страница описывает локальный MVP.
- Настроить HTTPS, `COOKIE_SECURE=true`, секреты, доверенную сеть backend / PostgreSQL и ограничение нагрузки на reverse proxy.
- Для нескольких процессов заменить локальный лимитер общим Redis-лимитером. Текущий лимитер работает в памяти одного процесса; за Next.js адрес клиента представлен адресом прокси.
- Настроить резервные копии, мониторинг без содержимого запросов, очистку истёкших сессий и неиспользуемых демоаккаунтов.
- Добавить восстановление пароля, проверку email и управление другими сессиями; в этом MVP есть регистрация, вход и выход, без почтовых отправок.
- Подключить каталоги по разрешённым договорами способам; проверить поставщика, обновление, цены и наличие. Доставка и оформление заказа выполняются на стороне магазина.
- Напоминания только внутри открытого приложения; фоновых push/email-задач нет.
- Медицинские и другие чувствительные поля не принимаются API профиля. Для их обработки нужен отдельный проектный и правовой процесс.
