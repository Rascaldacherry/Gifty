# Gifty AI

Работающее локальное MVP для персонального подбора подарков: Next.js + FastAPI + SQLAlchemy + PostgreSQL. Русский интерфейс с кремовой основой, лавандовыми акцентами и оригинальными SVG-иллюстрациями.

Без платных API доступны регистрация и вход, профили близких, редактируемая Gift DNA, быстрый и умный подбор, избранное, история, календарь, подарочные наборы, ручной импорт интересов, экспорт и удаление данных. Данные хранятся на backend и переживают перезапуск приложения.

Демокаталог содержит **условные идеи, иллюстрации и цены**, а не проверенные предложения магазинов. Кнопки открывают настоящую поисковую выдачу Ozon, Wildberries или Яндекс Маркета. Вымышленные прямые ссылки, наличие и рейтинги не используются.

## Требования

- Node.js 22 LTS и npm (минимум Node.js 20.9).
- Python 3.12 или 3.13.
- Docker Desktop с Compose для PostgreSQL; для быстрого запуска без Docker можно использовать SQLite.
- VS Code по желанию. Рекомендуемые расширения и задачи находятся в `.vscode/`.

Все команды ниже выполняются в PowerShell из корня репозитория, если не указано иное. Для macOS/Linux вместо `backend/.venv/Scripts/python.exe` используйте `backend/.venv/bin/python`.

На Windows весь локальный запуск можно выполнить одной командой:

```powershell
./scripts/dev.ps1 -Sqlite
```

Скрипт создаст окружение при необходимости, установит отсутствующие зависимости, применит миграции и запустит оба сервера. Он также находит локальный Node.js в `%LOCALAPPDATA%/GiftyDev`, подготовленный при разработке в этом окружении. Держите терминал открытым; `Ctrl+C` останавливает оба сервера. Для PostgreSQL используйте скрипт без `-Sqlite` после настройки `.env` и запуска базы.

## Быстрый запуск без Docker и API-ключей

Установка backend:

```powershell
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.lock.txt
backend/.venv/Scripts/python.exe -m alembic -c backend/alembic.ini upgrade head
```

Если корневого `.env` нет, автоматически используется `backend/gifty.db` (SQLite). Если `.env` уже настроен на PostgreSQL, для SQLite задайте переменную в этом терминале:

```powershell
$env:DATABASE_URL = "sqlite:///" + ((Join-Path (Get-Location) "backend/gifty.db") -replace '\\', '/')
```

Примените миграции после изменения базы. Запустите API в первом терминале:

```powershell
backend/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000 --no-access-log
```

Во втором терминале:

```powershell
npm --prefix frontend ci
npm --prefix frontend run dev
```

Откройте **http://localhost:3000**. Создайте аккаунт либо нажмите **«Попробовать демо»** — будет создан отдельный изолированный аккаунт с четырьмя вымышленными людьми и готовыми подборками. Демоаккаунт доступен по cookie в течение срока сессии; для постоянного входа по паролю используйте обычную регистрацию.

Если backend работает по другому адресу, скопируйте `frontend/.env.example` в `frontend/.env.local`, измените `API_ORIGIN` и перезапустите frontend. Секреты провайдеров в этот файл не помещаются.

В VS Code после установки и миграции можно выполнить **Terminal → Run Task → Gifty: dev**. Задачи запускают API и frontend в отдельных терминалах. Если PowerShell блокирует `npm.ps1`, используйте `npm.cmd` вместо `npm`.

## Основной запуск с PostgreSQL

```powershell
Copy-Item .env.example .env
docker compose up -d db
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.lock.txt
backend/.venv/Scripts/python.exe -m alembic -c backend/alembic.ini upgrade head
```

Далее запустите backend и frontend командами выше. `.env.example` уже содержит URL локальной PostgreSQL. Измените пароль при использовании вне локальной разработки. Если ранее задавали `$env:DATABASE_URL` для SQLite, удалите переменную из текущего терминала командой `Remove-Item Env:DATABASE_URL`, чтобы настройки взялись из `.env`.

Полный стек в контейнерах:

```powershell
Copy-Item .env.example .env
docker compose --profile full up --build -d
```

Frontend: http://localhost:3000. API: http://localhost:8000/api/health. Документация API: http://localhost:8000/docs (выключена в `APP_ENV=production`). Backend автоматически применяет Alembic-миграции в контейнере. Данные PostgreSQL хранятся в volume `postgres_data`.

Остановить контейнеры с сохранением данных:

```powershell
docker compose --profile full down
```

## Что можно проверить

1. Создать аккаунт, пройти знакомство и добавить получателя.
2. Указать возраст или категорию, день рождения, интересы, бренды и нежелательные категории.
3. Открыть Gift DNA, изменить веса, импортировать разрешённые заметки, подтвердить или исправить предположения. Удаление импорта удаляет исходный текст и полученные из него интересы.
4. В помощнике выбрать получателя, повод и бюджет. Например: «Любит рисовать и корейскую культуру, бюджет до 3000 рублей, без косметики». Бюджет текста может только уменьшить бюджет формы.
5. Выбрать умный режим и ответить на три уточнения.
6. Просмотреть до восьми идей с объяснениями, отфильтровать категории, изменить сортировку и сохранить подарок.
7. Открыть поиск магазина по названию. Цена и наличие уточняются в магазине.
8. Собрать тематический набор, заменить один товар, сохранить весь набор. Общая сумма не превысит бюджет.
9. Добавить событие или день рождения. Напоминание появится под колокольчиком в заданный срок.
10. Записать подаренный товар в профиле — он будет исключён из следующих рекомендаций.
11. Перезапустить приложение, войти и открыть историю подборок или избранное.
12. В настройках изменить критерии, выгрузить JSON или удалить аккаунт и связанные данные.

## Структура

```text
backend/
  app/
    models.py                 # сущности, связи, каскадное удаление
    schemas.py                # Pydantic-контракты
    security.py               # scrypt, серверные сессии, HttpOnly-cookie
    routes/                   # авторизация, люди, подборы, события, данные
    services/
      recommendations.py      # Gift Recommendation Engine
      ai.py                   # Demo / YandexGPT / GigaChat / совместимый API
      catalog.py              # mock и адаптеры разрешённых экспортов
      interests.py            # ручной Social Interest Analyzer
      speech.py               # SpeechKit и нормализация аудио
  migrations/versions/        # Alembic, начальная миграция всех таблиц
  tests/                      # интеграционные тесты API и алгоритмов
frontend/
  src/app/                    # страницы App Router и серверный /api proxy
  src/components/             # оболочка, чат, профили, карточки, Radix UI
  public/products/            # локальные оригинальные SVG-иллюстрации
  tests/                      # Playwright-сценарии в реальном браузере
docs/architecture.md          # потоки данных, интеграции, ограничения MVP
compose.yaml
.env.example
```

Подробнее о сущностях, ранжировании, безопасности и границах MVP: [архитектура](docs/architecture.md).

## Настройка внешнего ИИ

По умолчанию `AI_PROVIDER=demo`. Анализ локальный и детерминированный; сложные отрицания и нестандартные интересы могут потребовать уточнения.

Для внешнего провайдера задайте настройки **на backend** в корневом `.env`, перезапустите API, предоставьте разрешение в настройках аккаунта и отдельно включите внешний анализ в дополнительных параметрах чата. Включать внешнюю обработку следует после проверки оператором необходимых оснований, условий провайдера и инфраструктуры. Одного разрешения дарителя недостаточно для всех сценариев обработки данных других людей.

```dotenv
EXTERNAL_PROCESSING_ENABLED=true
AI_PROVIDER=yandex
AI_API_KEY=your-server-key
YANDEX_FOLDER_ID=your-folder-id
```

Для GigaChat: `AI_PROVIDER=gigachat`, `GIGACHAT_ACCESS_TOKEN` и при необходимости `AI_MODEL`. Access token должен обновляться оператором; автоматический OAuth-refresh не реализован. Проверка TLS включена: при необходимости настройте доверенные сертификаты, не отключайте её.

Для совместимого Chat Completions API: `AI_PROVIDER=openai_compatible`, `AI_BASE_URL=https://.../v1`, `AI_API_KEY`, `AI_MODEL`. Провайдер должен поддерживать структурированный JSON-ответ. Сервер валидирует результат; внешняя модель не создаёт каталог, цены и ссылки.

Ни один ключ не использует префикс `NEXT_PUBLIC_` и не попадает в браузер. Без разрешения и серверного включения внешние обращения блокируются.

## Голосовой ввод

Задайте `SPEECHKIT_API_KEY`, при необходимости `SPEECHKIT_FOLDER_ID`, разрешите внешнюю обработку на сервере и распознавание голоса в настройках аккаунта. Доступ к микрофону запрашивается только при нажатии записи. Запись — до 25 секунд / 1 МБ; распознанный текст показывается для исправления до отправки.

Firefox с OggOpus работает напрямую. Для Chrome/Edge (WebM/Opus) установите **FFmpeg** в PATH backend; Docker-образ уже содержит FFmpeg. Аудио преобразуется в памяти и не сохраняется. При отсутствии настроек интерфейс показывает понятное сообщение и предлагает текстовый ввод.

## Каталоги и источники интересов

`OZON_CATALOG_FILE`, `WILDBERRIES_CATALOG_FILE`, `YANDEX_MARKET_CATALOG_FILE` — пути к JSON-экспортам, на использование которых у оператора есть необходимые права. Формат: [catalog.example.json](docs/catalog.example.json). Этот файл — пример схемы, его условные значения нельзя выдавать за реальные предложения. Для контейнера смонтируйте экспорт read-only и укажите контейнерный путь.

После перезапуска API экспорт валидируется и приводится к `Product`. Для прямых карточек разрешены только HTTPS-URL нужного магазина; при `product_url=null` открывается поиск. Seller API и парсинг потребительских каталогов не используются. Официальные интеграции VK/Telegram не подключены; работает ручной импорт разрешённых текстов со ссылкой и источником каждого предположения.

## Проверки

Серверные тесты используют отдельную SQLite in-memory базу для каждого теста, не затрагивают ваши данные и не обращаются к внешним API:

```powershell
Push-Location backend
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe -m ruff check app tests
.venv/Scripts/python.exe -m alembic check
Pop-Location
```

Frontend:

```powershell
npm --prefix frontend run lint
npm --prefix frontend run typecheck
npm --prefix frontend run build
```

Сквозные браузерные сценарии (API и frontend должны быть запущены):

```powershell
Push-Location frontend
npx playwright install chromium
npm run test:e2e
Pop-Location
```

Если Chrome уже установлен, можно задать `$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'` и пропустить загрузку Chromium. Сценарии проверяют подбор, ограничения, избранное, сохранение истории, профили, импорт, умный режим, голос без ключа, календарь, наборы и мобильную навигацию. Они создают отдельные демоаккаунты в запущенной базе; используйте тестовую установку. Скриншоты сохраняются в `.artifacts/`, диагностические trace-файлы — в `frontend/test-results/`.

Для тестовой установки задайте backend `APP_ENV=test` и отдельный `DATABASE_URL`: это отключает лимитер только в тестовом процессе. При проверке обычной dev-установки задайте `$env:E2E_THROTTLE = 'true'` — сценарии будут выполняться с паузами, чтобы не превышать её лимиты. Дополнительно проверяются экспорт, удаление аккаунта и очистка предыдущих данных при смене пользователя даже при ошибке API.

## Миграции и сборка

```powershell
backend/.venv/Scripts/python.exe -m alembic -c backend/alembic.ini upgrade head
backend/.venv/Scripts/python.exe -m alembic -c backend/alembic.ini revision --autogenerate -m "describe change"
npm --prefix frontend run build
```

Node-запуск production-сборки вне Docker: `npm --prefix frontend run start`. Standalone-образ для Docker собирается отдельным Dockerfile. Для локальной разработки используйте `npm run dev`.

Зависимости frontend фиксированы в `package-lock.json`; backend — в `requirements.lock.txt`. `requirements.txt` задаёт допустимые диапазоны для обновления. После обновления зависимостей повторите тесты и сборку.

## Эксплуатационные границы

Лимитер в MVP локальный для одного процесса: 20 изменений авторизации, 15 запросов к подбору/голосу и 240 остальных запросов в минуту на адрес клиента. При превышении возвращается 429 с `Retry-After`. За Next.js адресом клиента для backend является адрес прокси; для публичного многопользовательского сервиса нужен доверенный reverse proxy и общий лимитер.

Нет рассылок, скрытого сбора данных, автопокупки, фоновых push/email, восстановления пароля и подтверждения email. Медицинские сведения и другие чувствительные поля в профилях не поддерживаются. Политика в приложении описывает локальное MVP; перед публичным запуском нужны реквизиты оператора и проверка обработки персональных данных. Подробный список дальнейших эксплуатационных работ — в [архитектуре](docs/architecture.md#ограничения-mvp-перед-публичным-запуском).
